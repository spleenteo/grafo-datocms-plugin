# V1.1 — Zoom strokes and neighbour labels: plan

**Goal**: zoomed in, the graph stays thin (hairline links, small arrows); a selected hub doesn't pile up dozens of neighbour labels.

**Scope**: `src/graph/renderGraph.ts`, `src/graph/graph.module.css`. No handle or data-layer change. Reuses `pickLabelBudget` (`src/graph/labelBudget.ts`).

## Global constraints

- Gate: `npm run typecheck && npm test && npm run build`, then the headless harness (lessons.md): mount, select, filter, zoom, no page errors.
- `--label-k` (= max(1, k), written on the root svg by the zoom handler, exact at zoom end) is the only per-zoom write besides the two marker elements. No per-node or per-link writes on zoom.
- Below k = 1 nothing changes from today.

## T1 — Strokes and arrows at screen size

- CSS: divide every stroke width that lives in graph units by `var(--label-k, 1)`: `.link` (0.75), `.link.hi` (1.25), `.dot` (1.5, draft 2, ctx 1.5), `.ring` (1.5), focus-visible dot (2.5); also the draft `stroke-dasharray` (3 2). `.label` stroke already scales with its box: leave it.
- Markers: keep the two marker elements in variables; whenever `labelK` changes (same places that write `--label-k`), set `markerWidth`/`markerHeight` to `ARROW_SIZE / labelK` and `ARROW_SIZE_HI / labelK`.
- `draw()`: the line end offset uses `ARROW_OVERSHOOT / labelK` and the ring/gap constants (`5`, `3`, start offset `1`) divided by `labelK`, so arrow tips still touch the node edge. Between ticks after a zoom the offset is stale by a fraction of a pixel: acceptable, say so in a comment. The same `labelK` is read, nothing new written per zoom.

Done: harness at k = 6 on Acacia: links ~0.75 px on screen, arrows ~4.5 px, tips at the dot edge.

## T2 — Neighbour label cap (depends on T1: same file)

- New constant `NEAR_LABEL_BUDGET = 20`.
- New state `nearLabelIds: Set<string>`: the focus id plus `pickLabelBudget(neighbours of focus with positions, viewBox(), NEAR_LABEL_BUDGET)`; empty with no focus. When the focus has ≤ 20 visible neighbours it is simply focus + all of them (no view filter: off-screen neighbours of a small focus keep their label as today).
- `labelOn()`: replace `focusSet.has(n.id)` with `nearLabelIds.has(n.id)`. `.near` (no dimming) still uses `focusSet`; only labels are capped. "All" mode unaffected (root class).
- Recompute `nearLabelIds` in `paint()` when the focus changes (repaint labels for old ∪ new ids, O(degree)), in `paintAll()`, and in `refreshBudget()` (zoom end, sim end, drag end) so panning around a hub updates which neighbours are labelled.
- The fit's `labelShown` keeps reading `shownIds`: no change.

Done: harness, Cosmea selected (82 neighbours): ≤ 21 labels from the focus set plus the 40 Smart budget; Gestart node with < 20 neighbours labels all of them.
